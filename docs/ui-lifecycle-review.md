# UI lifecycle review

Reviewed conversation rendering, code analyzer progress and repository workflows, file previews, tool disclosures and approvals, shared controls, settings, authentication, and task pages. Fixes preserve the existing components, semantic colors, spacing, and keyboard behavior.

The conversation owns one progress card per durable job ID. Streamed tool results remain disclosures. Switching conversations must dispose their requests, timers, previews, and local action state. Removing a job or dismissing source results must keep those interfaces removed when earlier requests finish.

| Before                                                                                  | After                                                                                                                 | Why                                                                                  |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Discovery stopped for empty or completed job lists.                                     | Active discovery runs every 2 seconds; idle discovery runs every 15 seconds and refreshes on focus or tab visibility. | Delegated work can appear after chat settles; jobs removed elsewhere must disappear. |
| Repeated job entries could mount duplicate cards.                                       | Job IDs are deduplicated before rendering.                                                                            | One card owns each polling and report-saving lifecycle.                              |
| A new conversation fell back to the last created thread ID.                             | Analyzer interfaces use the active conversation ID.                                                                   | New chats must not load or operate on previous chats’ resources.                     |
| Welcome suppression remembered that jobs once existed.                                  | The parent receives both visible and empty job states.                                                                | The welcome returns after the final job disappears from an empty chat.               |
| Reusing a standalone job card retained its released/busy state.                         | Each job ID starts a fresh component session; hook errors and timestamps are scoped to that ID.                       | State from one job must not disable or mislabel another.                             |
| Every completed card offered workspace release, including during another active job.    | One release action appears after all listed jobs finish.                                                              | The conversation shares one workspace, which active analysis still needs.            |
| Report downloads and workspace release inferred ownership from the URL.                 | Actions use the job’s owning conversation when supplied.                                                              | Navigation must not redirect an action to another conversation.                      |
| File previews survived conversation changes, or reopened when removed files reappeared. | The shared preview provider has a conversation key and forgets removed paths.                                         | Preview state must follow the current conversation and explicit user actions.        |
| Tasks/Files expansion survived a thread switch or removal of its selected collection.   | Expansion resets when the thread changes or its selected collection disappears.                                       | Avoid empty expanded panels and stale local state.                                   |
| Closing repository results left pagination requests running.                            | Dismissal aborts the pending browse request and clears its busy state.                                                | A late page must not reopen dismissed results.                                       |

The new lifecycle regression runs under React Strict Mode and checks repeated results, late discovery, removal, stopped polling, delayed responses across conversation switches, preview cleanup, and action-state reset. Analyzer views pass overflow and axe WCAG A/AA checks at 320, 768, 1024, and 1440 pixels. Browser screenshots are saved under `/tmp/conversation-ui-lifecycle`.

Existing browser coverage also exercises preparation, cancellation, reconnects, handoff, report delivery to Files, source selection, reload recovery, tool approvals, reduced motion, history scrolling, settings drafts, authentication, task pages, light/dark themes, and 200 percent text enlargement. Two older browser fixtures were updated to supply their current auth/helper dependencies.

Validation passed: 512 unit tests and 28 browser checks, including grouped browser suites. ESLint, TypeScript, formatting, and the production build also pass. The default unit command skips opt-in browser tests; the browser checks were enabled and run separately.

Verification uses deterministic API fixtures. Live worker/backend integration and physical touch devices were not exercised. Idle discovery may take up to 15 seconds to reflect a newly created or removed job; returning focus refreshes immediately. Workspace release availability reflects the five jobs returned by the existing conversation endpoint; server authorization remains authoritative.
