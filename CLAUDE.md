# CLAUDE.md

Guidance for working in this frontend repository.

## Frontend

This repository is the Next.js frontend root.

Markdown rendering goes through `MarkdownContent` and supports GitHub-flavored Markdown (via `remark-gfm`), LaTeX math (via `remark-math` + `rehype-katex`, with `katex.min.css` imported globally), and Prism-highlighted code blocks.

File previews use `FileContentView`: Markdown files pass `mode="document"` to preserve authored syntax, while chat retains provider-specific normalization. Document mode lifts a leading YAML frontmatter block (`src/lib/frontmatter.ts`) into a metadata panel so CommonMark does not render it as a rule plus a setext heading. Preview and Source are limited to 50,000 characters before parsing; Copy, Download, and editing use the complete file. Keep typography customizations under `theme.extend.typography` so the default prose styles remain available.

`FileContentView` offers Preview/Source modes for `.md` files. `src/app/utils/artifactPreview.ts` applies display-only transforms to agent artifacts: deepagents conversation-history files (`conversation_history/*.md`, LangChain XML message dumps) are rebuilt into a transcript with `read_file` line-number gutters stripped and tool output fenced, and legacy plain-text tool records offloaded as `/_artifacts/<user>/<thread>/<domain>/*.md` open in Source mode. Stored files are never rewritten; the transform runs on the (possibly bounded) preview only.

The Files list shows root thread `files` plus an overlay of files a delegated subagent saved but has not yet handed back (`src/lib/pending-files.ts`). Subagent writes reach the root thread only when its `task` returns, and the Agent Server cannot read dynamic subagent namespaces, so `useChat` collects them from `updates|tools:<id>` stream events and marks them "Saving" until the root state includes them or the run settles. Chat uploads and deletes run as separate maintenance runs outside the stream, so the composer calls `refreshFiles` afterwards.

The composer toolbar's model quick picker (`src/app/components/composer/ModelQuickPicker.tsx`, between the approval mode and the `$ skills · @ files` hint) edits the same per-user settings as Workspace › Models: model, reasoning effort, adaptive thinking, and max output tokens. Both surfaces show product names from `src/lib/model-names.ts` (`claude-haiku-4-5` → "Claude Haiku 4.5"; the exact ID stays in the tooltip and in every API call) and share the linked-control rules in `src/lib/model-controls.ts` (`nextModelDraft`/`switchModelDraft`). `useModelSelection` saves optimistically after a short pause, one request at a time, and reverts on failure. `apiSetUserModel` broadcasts `MODEL_SELECTION_CHANGED_EVENT` so the other surface follows. Browser evidence: `MODEL_PICKER_BROWSER_TEST=1 node --import tsx/esm --test tests/model-quick-picker-browser.test.mjs`.

Runtime events that are neither the user's nor the assistant's words render through the shared `DisclosureCard` (`src/app/components/DisclosureCard.tsx`): context handoffs (`ContextSummaryCard`), completion checks, and grader revision requests. Detection keys on message markers and stream payloads, never on the graph id, so every agent that compacts context or installs the native rubric renders alike. Completion verification (`src/lib/task-outcome.ts`) treats `values.task_outcome` (TaskOutcome v1) as authoritative and restores it after refresh. A root `custom` `task_outcome` event only refines that value in place (`reduceTaskOutcome`): it cannot choose an execution, change its task, revision or answer (`candidate_message_id`), or undo a terminal status. Root `rubric_evaluation_start|end` events add per-check detail while streaming; subgraph events are ignored, and streamed grader tokens (`rubric_grader_configured_model` in their stream metadata) never render. `TaskOutcomeStatus` attaches under the answer it judges and replaces that run's persisted `task-status:<execution>:<answer>` notice; earlier notices stay as compact `TaskStatusNotice` rows. "Checking completion" shows only while a run is live and the checked answer is still the latest turn (`verificationIsLive`), and an earlier answer's outcome never hides a new turn's activity (`isLatestTaskOutcome`). Grader revision requests (`lc_source: "rubric_grader"`) render as numbered `RubricRevisionCard`s, never as user bubbles. Simple answers (`reason_code: "simple_answer"` or `"not_evaluated"`) show nothing, and reason codes and grader error text are never displayed verbatim. Browser evidence: `TASK_OUTCOME_BROWSER_TEST=1 node --import tsx/esm --test tests/task-outcome-browser.test.mjs tests/task-outcome-cards-browser.test.mjs` (see `docs/evidence/task-outcomes/README.md`).
